# Digital Cabinet（数字内阁）

在所有低头干活的执行窗口之上，单独设立一层**不抢方向盘、严格只读、专盯全局轻重缓急与个人分寸感**的统筹参谋。

## 何时调用

- 同时开着多个 AI 编程/研究窗口，感觉脑子快变成“人肉中转站”，想一眼看清**哪些事卡着等拍板、哪些窗口还在按旧废稿跑、哪些隔夜半截事快沉底了**；
- 刚在某个窗口纠偏了一次 AI 的笨决定，想把这次拍板背后的**分寸与前提**沉淀成跨窗口通用的长期默契，避免换个窗口又重头教一遍；
- 准备让 AI 在夜间或后台自主往前推一步，需要事先过滤掉“给分析报告再写一份分析报告”式的**假装很忙（安全感表演）**。

## 四条核心铁律

1. **严格只读与显式目录授权**：
   - 默认只扫描用户显式传入的会话目录或内置合成样例，**绝不扫描全盘或未授权隐私目录**，也绝不擅自替用户合入主干、改线上配置或对外发消息。
2. **状态优先于单日增量（跨天咬死未完事，随口一句即销账）**：
   - 凡处于 `waiting_owner`（等拍板）或 `stalled`（聊到一半卡住）的事，哪怕隔天原窗口 `0` 新消息，也必须跨天保留在待办视野里，绝不能因为“今天没动静”就静默消失；
   - 一旦用户在任意窗口明确说“这块不用管 / 先放放 / 作废”，立刻凭原话出处标记为 `dropped`，从此不再反复催办。
3. **不堆死条框，只记「好坏例子 + 为什么 + 适用前提」**：
   - 严禁往系统提示词里硬塞几十条机械禁令（如死卡字数、死限列数），那只会把模型逼成满嘴双重否定“并非不能兼容……锅你自己背”的不粘锅；
   - 每次沉淀个人习惯，必须写清四要素：**触发处境 + 好判断（Good） + 坏判断（Bad） + 背后的为什么与适用前提（Why & Premise）**（例如：小样快测能放过的非阻断警告，正式上线前绝不能顺手划掉）。
4. **反“安全感表演”门禁（推进真交付，拒绝空转套娃）**：
   - 评估后台或夜间自主任务时，若候选动作只是“把昨天的分析报告再离线总结/分析一遍”而产生 `0` 实质验证或可回退代码推进，直接拦截叫停，宁缺毋滥。

## 快速执行入口

1. **零配置 10 秒体验内置合成多窗口样例**：
   ```bash
   python3 scripts/cabinet.py demo --out ./cabinet-demo-out
   ```
2. **扫描指定本地会话目录生成四象限可展开 `.html` 简报**：
   ```bash
   python3 scripts/cabinet.py scan --dir /path/to/selected/sessions --playbook ./decision-playbook.md --out ./cabinet-out
   ```
3. **追加沉淀一条「好坏判断 + 为什么 + 适用前提」默契**：
   ```bash
   python3 scripts/cabinet.py learn \
     --playbook ./decision-playbook.md \
     --scene "导出脚本或小样试跑出现非核心字段空值/警告" \
     --good "小样验证阶段给默认短横线先行跑通主流程，并在简报尾注标明前提；正式上线前补齐上游空值校验" \
     --bad "小事弹框停工干等人工拍板，或正式上线时顺手沿用小样阶段的放行豁免" \
     --why "人的注意力只该花在不可逆取舍上；脱离适用前提照搬旧豁免会埋下线上暗雷" \
     --premise "仅限本地小样/草稿分支试跑；切换至正式发布环境时此豁免自动失效"
   ```

详细三本账结构与反套娃检查单见 [`references/three-ledgers-and-anti-theater.md`](references/three-ledgers-and-anti-theater.md)。
